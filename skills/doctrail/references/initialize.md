# Initialize or retrofit

Use this workflow for an existing project, including projects with only code and Git. Match depth to project size; a small tool may need only README, usage and one decision index.

1. **Inspect the baseline.** Read applicable project instructions, worktree status and current entry points. Run the inventory helper. Identify current interfaces from source/config/tests and note existing doc conventions. Preserve unrelated uncommitted work. A repository with no Git is supported, with historical coverage explicitly unavailable.
2. **Freeze a small acceptance list.** At minimum: a new reader can find the main operation; an agent can find the constraints for a changed capability; current behavior and history are distinguishable; existing human content survives; local links and decision relationships are checked. These criteria guide work, not a mandatory extra approval step.
3. **Make a disposition map.** For relevant existing files choose retain, update, merge, archive or investigate, with a reason and destination. Never classify something as obsolete solely because of its age. Keep source links or compatibility stubs when moving linked files. Do not mass-delete old docs. Check existing links before editing so inherited defects can be reported separately.
4. **Investigate bounded history.** Start with commit subjects and relevant paths, then inspect selected commits using `git show` and rename-aware history when necessary. Look for actual reversals, repeated implementation changes and references to tests/issues. Keywords are leads, not proof. Increase the history window only for unresolved questions; report truncation, shallow clones, missing branches and unavailable external discussions. Do not fetch branches or PRs unless needed and authorized. Never feed the entire log or raw conversation history into context.
5. **Reconstruct meaningful decisions.** Follow [decision records](decisions.md). A code diff supports what changed. Commit explanations support attributed rationale, but are not independent proof that a design is correct. When records disagree, preserve the disagreement and state the current implementation separately. Do not create an invented ADR for every commit.
6. **Build a reading path.** Follow [layout](layout.md). Prefer improving existing paths over renaming everything. Current guidance links to the relevant history. Add a brief routing instruction to the existing agent entry only within the requested scope; never replace project governance.
7. **Verify.** Check links and optional decision metadata; compare relevant commands/options with source or help output. Run safe, relevant documented examples when feasible. Record unexecuted, unavailable or failing checks honestly. Do not run a project's deploy, migration or model spending just for documentation.
8. **Deliver a baseline.** Report inspected revision and scope, migration map, newly recoverable historical choices, check results and unknowns. Keep intermediate inventory/history reports private by default; they may expose filenames or commit subjects. Repeat runs reconcile existing records by topic and evidence identity before adding new ones.

Do not make the task depend on answering optional naming or directory preferences. Use the existing project conventions unless they prevent navigability or factual separation.
